# 账号重新授权提醒

## 问题与用户

本机用户的上游 OAuth 凭据失效后，代理 SDK 可能已确认该账号无法继续认证，但账号卡片只显示名称和额度，用户不知道应重新登录。

## 流程与状态

- 已保存账号在服务运行期间，由代理 SDK 的实时账号状态判断是否需要重新授权。仅认证错误 `unauthorized` 或 `invalid_grant` 触发提醒；限流、网络故障、一般续期失败和额度查询错误不触发。
- 需要重新授权的账号卡片显示红色文字提醒和「重新授权」按钮。提醒属于该账号，不影响其他账号。普通添加登录入口继续保留。
- 点击卡片按钮打开对应上游的浏览器登录流程。同一时间仍只能进行一个登录，原有取消登录入口可取消。
- 重新授权只接受卡片对应的同一个账号。若用户在浏览器中选择同平台另一账号，应用报错并拒绝保存新凭据；原账号保持不变。失败或取消后提醒继续由 SDK 当前状态决定。
- 成功保存同一账号的新凭据后刷新账号和额度；SDK 确认认证恢复后移除提醒。
- 服务停止、启动失败或应用重启后尚未启动服务时，不显示历史提醒，也不凭凭据文件中的过期时间推测失效。
- 登录结果与读取失败沿用现有 toast 错误反馈；界面不展示访问令牌或刷新令牌。

## 非目标

不主动探测厂商认证端点，不因额度接口单次 401 判定失效，不自动打开登录页，不保存跨重启的失效快照，也不改变代理请求的重试和续期策略。

## 验收

1. 服务运行且 SDK 将某账号标为 `unauthorized` 或 `invalid_grant` 时，仅该卡片出现红字和重新授权按钮；其他 SDK 错误不出现。
2. 停止服务后提醒消失，重新启动后只按新服务的 SDK 状态显示。
3. 卡片按钮启动该账号所属平台的现有浏览器登录；取消和登录失败显示原有反馈，账号文件不被误改。
4. 登录为另一个账号时拒绝保存并提示错误；登录为原账号并保存成功后，列表和额度刷新，认证恢复时提醒消失。
5. Codex、Grok、Claude、Gemini、Kimi 两种登录和 Devin 的已有账号均可按上述规则重新授权；界面不泄露令牌。
