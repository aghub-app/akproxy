# 本地代理

## 问题

编程工具要调用 Codex、Grok、Claude、Gemini、Kimi、Devin 和自定义的 OpenAI 兼容上游。这些账号和参数现在散落在 CLIProxyAPI 的配置里。本应用把「改配置」和「启动本机 HTTP 服务」放进同一个窗口。

## 用户

使用这台电脑的一个人，把本机上的编程工具指到这个服务。不是多用户产品，也不替别人托管。

## 用户故事

- 我在对应上游的页面登录，启动后得到一个地址和一把客户端密钥，把工具指过去。
- 我在「设置」里改密钥、出站代理或路由。改动马上写入，服务还在跑时直接生效，不用先停止。
- 我在「设置」里改监听地址或端口。改动马上写入，服务继续用原来的监听。导航栏提醒可以考虑重启。我点重启后，新的监听才生效。
- 表单没有的字段留在配置文件里。之后再改某一页，这些字段还在。

## 目标

- 一个窗口完成常用配置、浏览器登录和 HTTP 服务的启动、停止、重启。
- 配置和浏览器登录产生的账号属于这个应用自己的数据目录。
- 没有客户端密钥时，服务不能被启动，配置也不能被写成一份没有密钥的文件。

## 非目标

- Meta、AI Studio、Vertex 的单独登录。
- 应用内的原始配置编辑器。
- 插件、payload 规则、OAuth 模型别名、权重、请求级错误规则的表单。这些字段如果已经在配置文件里，保存表单时保留。
- 打开一份已经在用的 CLI 配置并就地接管。
- 内嵌或下载 CLIProxyAPI 的管理面板网页。
- 菜单栏常驻。应用退出后服务继续运行。
- Tauri，或把 CLI 二进制当子进程启动。

## 形态

窗口标题是 akproxy。业务界面文案用中文；应用更新使用 Wails 官方默认窗口及其语言，见 `app-updates.md`。

顶部是导航栏。导航栏显示服务是否在运行，以及客户端应该使用的地址，地址可以复制。导航栏右侧只有一个控制按钮，没有第二个服务按钮。

左侧是侧边栏，顺序固定：

1. Codex
2. Grok
3. Claude
4. Gemini
5. Kimi
6. Devin
7. 自定义 OpenAI
8. 设置

打开应用时落在「设置」。

右侧是当前项。设置和自定义 OpenAI 改完就写入，没有单独的保存按钮。

## 导航栏按钮

按钮上同时只出现一个动作：

| 条件 | 按钮 | 点击 |
| --- | --- | --- |
| 服务未运行 | 启动 | 用已保存配置启动 |
| 服务在运行，且已保存的监听配置等于这次启动实际绑定的监听配置 | 停止 | 停止服务 |
| 服务在运行，且已保存的监听配置不同于这次启动实际绑定的监听配置 | 重启 | 先停止，再按已保存配置启动 |

监听配置指 host、port 和 TLS。密钥、路由、出站代理和其他已写入的修改不改变按钮。服务在运行时，这些修改通过热重载生效。监听已经不同时，导航栏提醒可以考虑重启，按钮变成「重启」。

启动、停止和重启都按磁盘上已经写入的配置执行。

重启后的再次启动如果失败，服务停留在停止，并显示失败原因。按钮回到「启动」。

## 客户端密钥

客户端密钥是调用这个服务的凭证，不是上游账号的密钥。

- 第一次创建配置时生成一把客户端密钥。
- 写入之后，配置里至少有一把客户端密钥。零把密钥的写入失败，文件不变；正在运行的服务也不因这次写入而改变。
- 没有客户端密钥不能启动。只监听本机和监听所有网络接口都适用。
- 「设置」页能查看和复制客户端密钥。

## 页面

### 设置

这一页用三个标签组织。任何改动在可以写入时立即写入。端口还没填成 1 到 65535、自定义地址还是空的时候，先留在页面上，不写文件。

- 监听：监听范围（只本机、所有网络接口，或一个自定义 host）和端口。只本机写入 `127.0.0.1`。所有网络接口写入空 host。TLS 不在界面里改。已有的证书配置留在配置文件里，改这一页不会清掉。
- 密钥：一张客户端密钥表格。表头左侧是 API key，右侧是「新建 API key」，点击后直接生成一把密钥并写入，新行短暂高亮，并提示创建成功。表格里的密钥默认遮住，点击密钥切换显示，也可以复制或删除。不能写成空列表，也不能写成重复项。
- 高级：出站代理 URL，路由策略 `round-robin`、`weighted-round-robin`、`fill-first`，以及调试日志。管理密钥不在界面里改。已有的远程管理配置留在配置文件里，改这一页不会清掉。

路由的会话亲和和其他高级项不在这一页，留在配置文件里。改「设置」不清除它们。

### 有浏览器登录的上游

Codex、Grok、Claude、Gemini、Kimi、Devin 可以打开系统浏览器登录。登录写入应用自己的账号目录。服务是否正在运行都可以登录。登录完成后，正在运行的服务能用上新账号，不必重启。

每一页列出已经登录的账号。显示给人看的名称优先用邮箱，没有邮箱再用账号标签。不显示令牌或密钥文件内容。删除账号前要确认。删除后，正在运行的服务不再使用该账号。

Codex 和 Claude 的账号卡片显示这个账号当前的会话额度。进度条是厂商返回的已用百分比：Codex 来自 ChatGPT 的 5 小时和每周窗口，Claude 来自 Anthropic 的 5 小时、每周，以及有数据时的每周 Opus 和每周 Sonnet。读取用该账号自己的登录令牌，令牌不出现在界面上。其他平台没有这个额度接口，卡片不画进度条。

同一时间只能有一个登录。登录中可以取消。登录失败时显示原因。页面不展示登录过程的终端输出。

Gemini 的浏览器登录是 Antigravity 这条登录，不是单独的 AI Studio 或 Vertex 登录。页面名称用 Gemini。

Kimi 有两个浏览器登录：kimi.com 和 kimi.ai。

这些页面只有浏览器登录和账号列表，没有上游 API key 表单。已有的上游 API key 留在配置文件里。

### 自定义 OpenAI

一个列表。每一项有名称、base URL、API key 列表和模型列表（上游模型名、客户端别名）。四者都有的项会立即写入。别名留空时与模型名相同。还没填完的项先留在页面上，不写文件。

## 写入

没有单独的保存动作，也没有未保存离开提示。写入只改这一页负责的字段。配置文件里这一页不编辑的字段保持不变。用同一把上游 API key 或同一个 OpenAI 兼容名称匹配到的已有项，表单没有暴露的附加字段保持不变。API key 字符串或名称改了之后，不再匹配旧项，旧项的附加字段不跟着走。

## 默认配置

第一次启动应用时创建配置和账号目录：

- host 为 `127.0.0.1`，端口为 `8317`。
- 一把生成的客户端密钥。
- 路由策略 `round-robin`。
- 管理密钥为空，不允许远程管理，不下载管理面板。
- 调试关闭，出站代理为空，TLS 关闭。

## 失败

- 端口被占用、证书或私钥不可用、配置无法加载：启动失败，服务保持停止，显示原因。
- 停止没有在合理时间内结束：显示失败，不能把状态显示成已停止。
- 热重载只消费已经成功写入的文件。校验失败的编辑不会到达正在运行的服务。
- 退出应用时停止服务。正在进行的登录被取消。

## 验收

1. 侧边栏只有 Codex、Grok、Claude、Gemini、Kimi、Devin、「自定义 OpenAI」和「设置」。「设置」在最下面。没有 YAML 页，没有 Meta。
2. 导航栏右侧只有一个按钮。未运行时是「启动」，运行且监听未变时是「停止」，已写入监听与当前绑定不同时是「重启」，并提示可以考虑重启。
3. 设置里的改动在可以写入时立即写入。没有保存按钮，切换侧边栏不拦截。
4. 写入客户端密钥、自定义上游、出站代理或路由后，正在运行的服务使用新配置，按钮不变成「重启」。
5. 在「设置」页改 host 或端口并写入后，正在运行的服务仍绑定原来的地址，导航栏提示可以考虑重启，按钮变成「重启」。重启成功后绑定新地址。重启的后半段失败时服务为停止。
6. 零把客户端密钥不能写入，也不能启动。新配置自带一把可复制的客户端密钥。
7. Codex、Grok、Claude、Gemini、Kimi、Devin 的页面只有浏览器登录和账号列表，不显示上游 API key 表单。登录会打开系统浏览器，账号出现在对应页面，界面不显示令牌。
8. 改「设置」或自定义 OpenAI 之后，配置文件里该页不负责的字段仍在。
9. 退出应用后，服务不再监听。
