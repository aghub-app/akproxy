# 应用更新

## 问题与用户

akproxy 用户需要在应用里获取 GitHub 正式发布的新版本，无需重复手动下载安装包。

## 已确定的流程

- 正式版本启动及持续运行每 24 小时检查 `aghub-app/akproxy` 的正式 Release；忽略草稿和预发布。开发版不更新自身。
- 设置页保留手动检查入口和当前版本。
- 使用 Wails 官方默认更新窗口及默认流程：发现更新后自动下载、校验，用户点击重启才替换并启动新版。此前“点击下载更新”的方案由用户明确撤回，以简单实现为先。
- 下载不停止代理。更新重启后代理保持停止，不恢复之前的运行状态。
- 配置及账号目录不变。校验失败不得安装；网络失败可以重新检查重试。
- 支持 macOS arm64/amd64、Windows amd64、Linux amd64。当前开发机器只做 macOS 运行验证；另外两平台由各自 CI runner 构建，不宣称已经完成原生更新验收。
- 推送语义版本 tag 后，三平台构建产物及校验文件汇总到同一草稿 Release。维护者检查后手动发布，客户端才收到更新。

## 非目标

自定义更新弹窗、静默重启、预发布频道、恢复代理运行状态、系统包管理器安装更新。

## 验收

1. 启动及每 24 小时触发检查，手动入口也能打开官方窗口。
2. 无正式新版时不下载；预发布和草稿不参与升级。
3. 新版选择当前平台及架构的更新资产，下载后通过 SHA-256 校验才允许重启安装。
4. 下载时旧版可继续使用；用户点击重启后新版启动，原有配置和账号保留，代理不自动启动。
5. tag 构建生成可供首次安装及自动更新的产物，只有全部构建成功才能生成草稿 Release。
6. macOS 发布应用使用 Developer ID 签名并公证。证书和公证凭据只存于本机钥匙串或 GitHub Secrets。
