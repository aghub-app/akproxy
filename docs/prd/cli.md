# 命令行

## 问题

编程工具要指向本机代理。桌面窗口能复制地址和密钥，但用户还要自己打开终端、自己导出变量。本机上应该有一条 `akproxy` 命令，选出模型后直接把 Claude Code 或 Codex 指到这个代理。

## 用户

使用这台电脑的一个人。命令和窗口共用应用自己的数据目录。

## 用户故事

- 我打开应用后，终端里就有 `akproxy`，不用自己拷贝二进制，也不用管理员权限。
- 我运行 `akproxy model`，从本机代理的模型列表里选一个。这个选择是全局的一个模型。
- 我运行 `akproxy claude` 或 `akproxy codex`。这次进程使用本机代理和一把界面上看不到的客户端密钥，并带上已选模型。我在命令后面写的参数原样传给对应的 CLI。
- 还没选过模型时，这两条命令报错，并告诉我先运行 `akproxy model`。
- 本机没有 akproxy 应用时，命令报错，不自己把代理拉起来。
- 我不想要这条命令时，在设置里关掉。关掉后不再安装，并把已经加上的命令移除。

## 当前交付

这一步只接通命令解析、启动环境的组装、以及命令的安装。

- 安装包带有当前平台的 `akproxy` 命令行程序，和桌面程序分开。
- 偏好 `cliEnabled` 默认开。应用每次启动都自检：版本一致就保留已安装的命令，对不上就删掉再装。开发版本每次启动都覆盖安装。关掉开关就移除。
- 安装或移除失败时 toast 报错。toast 上有按钮，打开设置的「命令行」页。
- 「命令行」页只有一个开关。关掉即停用并移除。
- `akproxy claude`、`akproxy codex`、`akproxy opencode`、`akproxy pi` 用所选模型和第一把客户端密钥启动对应程序。后面的参数原样传过去。本机没有那个程序时失败，不自动安装。
- 数据目录里没有 `cli.json` 的模型 id 时，这四条命令报错并提示先运行 `akproxy model`。
- `akproxy model` 从本机代理读取模型列表，用 gum 的 choose 界面选一个，写入 `cli.json`。取消不改已有选择。服务没在听时失败，不启动代理。这一步用配置里的第一把客户端密钥请求模型列表。

## 之后再做

- 创建并保管界面上看不到的客户端密钥。模型列表和启动出去的 CLI 都改用这把密钥。

## 非目标

- 命令自己启动代理。
- 为 Grok、Gemini、Kimi、Devin、Meta 提供子命令。
- 每个 CLI 各记一个模型。
- 安装时弹出管理员密码。

## 验收

1. 新装或旧偏好文件没有 `cliEnabled` 时，开关为开。已安装命令的 `--version` 与当前应用版本一致时保留它；对不上、没有命令或读不出版本时删掉再装。开发版本每次启动都覆盖安装。
2. 安装失败时出现 toast，按钮进入设置的「命令行」页。关掉开关后，后续启动不再安装，并移除这次加上的命令和 PATH 项。
3. `akproxy model` 在服务可用时用 gum choose 列出模型。确认后 `cli.json` 只有所选 `model.id`，并在终端打出这个 id。取消、连接失败或没有模型时不改已有选择。
4. `akproxy claude`、`codex`、`opencode`、`pi` 在没有模型 id 时失败，提示先运行 `akproxy model`。有模型时启动对应程序，并把额外参数放在 akproxy 自己的参数后面。找不到程序时失败。
5. Claude 用本机代理地址、`ANTHROPIC_AUTH_TOKEN` 和所选模型。Codex 用临时 `-c` provider，密钥不出现在参数里。OpenCode 的配置只在本次进程的环境变量里。Pi 只用一个临时配置目录。这些命令不改用户原来的 Claude、Codex、OpenCode 或 Pi 配置。
