# 关于页与更新偏好

## 问题与用户

akproxy 用户需要在应用里看到软件是谁、什么版本、从哪来，并决定更新检查的节奏。当前更新行为（启动 + 每 24 小时检查、发现即下载）是构建时固定的，用户无法调整。

## 位置

「关于」是设置页的最后一个标签（监听、密钥、高级、用量、外观、关于）。侧边栏保持只有「设置」一个入口。

## 内容

- 头部信息区：应用图标、名称 akproxy、当前版本、平台与架构（如 macOS arm64）、上次检查结果与时间（如「已是最新版本」「检查失败」「发现新版本 vX.Y.Z · 上次检查 时间」）、检查更新按钮。发现新版本时该区显示「发现新版本 vX.Y.Z，查看详情」，点击重新打开发现新版本对话框。
- 当前版本为 `dev` 时，仅在版本旁显示短提交 hash；缺失时标为不可用，不用当前仓库状态冒充该二进制的信息。正式版本只显示版本号。
- 更新设置：自动更新开关、自动检查更新开关、检查间隔。
- 开源卡片标题为「自豪地采用 MIT 协议在 GitHub 上开源」；仅保留「源代码」（github.com/aghub-app/akproxy）和「问题反馈」（Issues）链接，点击后在用户的默认浏览器中打开。

## 更新偏好语义

- **自动检查更新**开：应用启动时检查一次，并按设定的间隔持续检查。关：启动和周期检查都不做，只保留手动检查；下面的检查间隔变灰且不能操作，原值保留。
- **自动更新**开：自动检查发现新版本后自动下载、校验，下载完成弹窗等用户重启（现状行为）。关：自动检查发现新版本只弹「发现新版本 vX.Y.Z」对话框，带「立即下载」和「忽略」，不自动下载。
- 手动「检查更新」不受自动更新开关影响，始终检查并直接下载。
- 间隔可选固定档位 1 小时、6 小时、24 小时、7 天，或自定义小时数（1–720）。默认 24 小时。
- 开关或间隔改动立即生效，不需要重启应用。自动检查从关到开会立即触发一次检查。
- 「忽略」只在本次检查周期内有效，下个周期发现同一版本会再次提示。
- 三个偏好的默认值等于当前行为：自动更新开、自动检查开、间隔 24 小时。
- 开发版本不执行任何自动检查；手动检查沿用现有提示「开发版本不执行更新」。

## 非目标

正式版本的构建详情；版权行；检查历史列表；跳过特定版本；预发布频道。界面语言由 `language-appearance.md` 规定。

## 验收

1. 设置页「关于」标签展示图标、名称、版本、平台架构、上次检查结果与时间、检查更新入口和仓库链接；仓库与问题反馈链接均在用户的默认浏览器中打开，打开失败时提示原因；发现新版本时可从头部重新打开对话框。
2. 关闭自动检查后，重启应用不触发检查，间隔到期也不触发；开启后立即检查一次并按间隔持续。
3. 自动更新关闭时，自动检查发现新版本弹「发现新版本」对话框，不下载；点「立即下载」进入现有下载流程，点「忽略」关闭对话框。
4. 自动更新开启时，行为与现状一致：发现即下载，完成后弹窗等重启。
5. 手动检查始终检查并下载；已是最新时只提示不弹窗（现状）。
6. 间隔选择自定义后输入小时数，保存即时生效；越界值不生效并提示有效范围。
7. 偏好在应用重启后保持。
8. 开发版显示其自身的短 hash；源码变动后重新构建显示新 hash。正式版不显示 hash，缺失的 hash 标为不可用。
