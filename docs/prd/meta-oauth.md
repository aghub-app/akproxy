# Meta OAuth 与额度

## 问题与用户

本机用户希望像其他上游一样，在 akproxy 中添加 Meta Muse 账号并调用 Muse 模型。Meta 使用设备码授权；验证码只出现在 SDK 的终端输出中，桌面窗口无法完成授权。

## 范围与流程

- 侧边栏和首页增加 Meta 入口。Meta 页沿用现有账号空状态、卡片、删除、重新授权及单登录槽。
- 点击添加或重新授权后，先取得设备码，再显示弹窗。弹窗显示验证码、自动复制成功提示、手动复制按钮，以及明确的「打开浏览器」链接；用户点击链接后在系统浏览器授权。自动复制失败时显示失败提示，手动复制仍可用。应用不自动打开浏览器。
- 授权期间可取消；关闭弹窗视为取消。设备码过期、拒绝授权、网络失败或订阅密钥签发失败时报告错误，不保存不可用账号。成功后关闭弹窗、保存到应用账号目录、刷新账号与额度，并把主窗口带到前面。
- 重新授权只更新选中的同一个 Meta 账号，换号时拒绝保存。
- Meta 卡片显示厂商返回的套餐名和可解析的滚动窗口、每周额度。缺少窗口时不显示假零；读取失败只影响该账号。额度总开关、后台刷新和手动刷新沿用其他上游。

## 非目标

不提供 Meta API key 编辑表单，不显示 OAuth 令牌或订阅密钥，不改变其他提供商的登录流程。

## 验收

1. Meta 页能从侧边栏和首页进入；添加账号时，弹窗展示设备码并自动复制，手动复制及浏览器链接可用。
2. 授权成功后，Meta 账号出现在页面，服务无需重启即可使用 Muse 模型；取消、超时、拒绝和签发失败不会新增账号。
3. 重新授权其他账号不会覆盖被选中的账号。
4. Meta 额度按厂商返回的窗口和套餐显示；缺失数据不会被当成零，失败不会阻断其他卡片。
