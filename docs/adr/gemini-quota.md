# Gemini 额度来自 Cloud Code 配额摘要

状态：已接受（2026-09-23）

## 背景

Gemini 页保存的是 Antigravity 登录。OpenUsage 用同一类令牌读取 Google Cloud Code 的配额：Gemini 共享池和非 Gemini 共享池各自的 5 小时与每周窗口。本地语言服务、对话库和估算花费不属于「当前可用额度」。

## 决定

- 用该账号已保存的访问令牌请求 `retrieveUserQuotaSummary`。先试 daily 端点，再试正式端点。返回可解析的摘要时，只采用 `gemini-5h`、`gemini-weekly`、`3p-5h`、`3p-weekly` 四个桶；缺剩余比例的桶不显示，也不当成用尽或未使用。
- 摘要不是配额响应时，才退到 `fetchAvailableModels`，仍没有窗口时再用 `loadCodeAssist` 的项目号调用 `retrieveUserQuota`。这两条旧路径只产生 5 小时窗口，并按池保留剩余比例最低的模型。旧路径省略的配额信息按该接口的约定视为该模型已用尽。
- 套餐名来自 `loadCodeAssist`。读取失败只省略套餐名。
- 访问令牌被拒绝且账号带有刷新令牌时，用 Antigravity 安装应用的 OAuth 客户端在内存里换一次访问令牌并重试。额度读取不改账号文件。
- 不连接本机 Antigravity 语言服务，也不扫描本地对话来估算花费。Kimi 仍没有厂商额度接口。

## 备选与后果

- 只读本地语言服务要求 Antigravity 正在运行，而 akproxy 的账号是自己的浏览器登录。
- 把摘要失败后的空结果当成「已用尽」会把缺字段显示成假零。可解析的空摘要停在「暂无额度窗口」。
- 刷新后写回账号文件可能和正在运行的代理抢同一份登录。额度读取只使用内存中的新访问令牌。

## 验证

解析测试覆盖四个桶、缺剩余比例、未知桶、空摘要，以及旧模型响应的分池。前端构建确认 Gemini 卡片能显示这些窗口。
