# Kimi 额度只读 Coding Plan

状态：已接受（2026-09-23）

## 背景

Kimi 页保存的是 kimi.com 和 kimi.ai 的 Coding 登录。CodexBar 用同一类访问令牌读取 Coding Plan 的 5 小时、每周和每月用量。开放平台余额是另一套 API key，不是这些登录。

## 决定

- 中国站请求 `https://api.kimi.com/coding/v1/usages`，国际站请求 `https://api.kimi.ai/coding/v1/usages`。账号里的域名或基址优先于 provider 名。请求带该账号的访问令牌；有设备号时带上 `X-Msh-Device-Id`。
- 优先使用响应里的比例池：`limit_5h`、`limit_7d`、`limit_month_total`。缺的池不显示。比例为 0 且同一窗口的旧次数计数可靠、重置时间相差不超过 2 秒、又没有每月比例池时，改用次数计算已用百分比。
- 没有比例池时，顶层 `usage` 是每周窗口，`limits` 的第一条是其声明时长的限速窗口，缺省按 5 小时。次数无法解析但限额有效时，该窗口按未使用显示。
- 套餐名来自同一响应的会员档位。未知档位保留原文；未指定档位不显示套餐名。响应能解析但没有任何可用窗口时，套餐名定为「免费版」，套餐名下说明没有 5 小时和每周额度。不把这种情况当成读取失败，也不补进度条。不读取网页订阅，也不读取开放平台余额。额度读取不刷新、不改写账号文件。

## 备选与后果

- 网页 `GetUsages` 需要浏览器 `kimi-auth` cookie。当前登录没有这枚 cookie。
- 开放平台余额不能表示 Coding Plan 的 5 小时和每周窗口。
- 比例池和旧次数同时存在时，以比例为准，避免把占位 0 和真实次数画成两条。

## 验证

解析测试覆盖比例池、缺窗口、0 比例回退、旧次数和套餐名。请求测试确认中国站和国际站打到各自的 usages 地址。
