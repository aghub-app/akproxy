# 监听变更由用户重启，其余已保存变更热重载

状态：已接受

## 背景

SDK 会监视 `config.yaml` 和账号目录，并把新配置应用到正在运行的服务。HTTP 监听在启动时绑定。运行中的配置更新不重新绑定 host、端口或 TLS。产品要求改密钥不必停止，改监听则明确变成「重启」。

## 决定

成功启动时记下这次实际绑定的 host、端口和 TLS。这个记录不跟着文件热重载改写。

按钮比较的是「已保存配置」和「这次绑定」：

- 相同且正在运行：停止。
- 不同且正在运行：重启。
- 未运行：启动。

保存本身不重启进程。热重载负责监听以外的已保存变更。

重启是取消当前服务并等它结束，再用已保存配置启动。后一次启动失败则保持停止，并保留失败原因。不自动再试，也不为了失败回滚到上一份监听。

## 备选

- 保存监听后自动重启。用户失去「先保存、再决定何时打断现有连接」的间隔，也和「按钮变成重启」冲突。
- 在热重载路径里重新监听。SDK 的更新入口不重新绑定，硬做会另起一套服务器生命周期。
- 重启时先启动新监听再停旧的。同一进程里换端口或换 TLS 仍然要先放开旧端口，失败时更容易留下不确定的绑定。

## 后果

- 已保存但尚未重启的端口，不是客户端该使用的地址。导航栏展示的是当前绑定地址；绑定和已保存配置不一致时，界面同时说明要重启。
- 停止、启动和重启都按已经写入的配置执行。设置改动立即写入，没有单独的保存步骤。
- 退出应用使用和停止相同的取消路径。

## 验证

- 运行中只改路由或上游密钥，绑定地址不变，按钮保持停止。
- 运行中改端口并保存，旧端口仍接受连接，按钮为重启。重启成功后只有新端口在监听。
- 重启时新端口不可用，旧端口不再监听，状态为停止并带有失败原因。
