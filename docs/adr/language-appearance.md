# 语言与外观偏好沿用 app.json

状态：已接受

## 背景

窗口文案在 React 页面和少量应用自有 Go 错误、原生菜单中。主题已有 CSS 浅色和 `.dark` 令牌，由系统媒体查询控制。更新与用量偏好已保存在应用自己的 `app.json`，不进入代理配置。

## 决定

- 在现有 `AppPrefs` 加入语言与外观选择，读取旧文件时补齐「跟随系统」，写入时校验允许值。仍以 `app.json` 为持久化事实来源。
- 直播模式是同一份偏好里的布尔值，缺省为关。打码只发生在界面展示账号名称时，不改写账号目录里的邮箱。
- React 使用仓库内的简体中文和英语文案表，运行时按已保存选择与系统语言解析。翻译只处理应用拥有的文字；外部错误详情和用户数据不改写。应用自有 Go 错误在界面边界转换为当前语言，不改变现有 Wails 调用契约。
- 外观沿用 CSS 的 `.dark` 类与系统媒体查询；手动选择时覆盖媒体查询。窗口启动时读取已保存的外观，避免主题覆盖与系统主题不一致。
- 自定义「关于」菜单启动时使用已保存的手动语言，窗口加载后按 WebView 解析的系统语言同步；语言偏好变化时更新菜单文案。系统提供的菜单项由操作系统处理。

## 备选与后果

- 新增 i18n 或主题依赖会引入现有两个语言、两个配色不需要的运行时机制，因此使用现有 React 状态、`Intl` 和 CSS。
- 把偏好写入 `config.yaml` 会混入代理配置并可能丢失未知字段；沿用 `app.json`。
- 应用自有错误仍保留现有 Go 文本接口，界面负责本地化；若今后有多种客户端消费这些错误，再考虑稳定的错误码契约。

## 验证

测试旧偏好升级、允许值校验、语言解析及应用错误转换；构建前端与桌面应用，并在真实窗口验证即时切换、系统跟随和重启保持。
