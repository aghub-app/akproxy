# 迁移 Wails v3 并复用官方更新器

状态：已接受

## 背景

Wails v3 迁移已独立提交，见 `wails-v3.md`。现有 CI 仅将 DMG 上传为 Actions artifact；本变更接入官方更新器和三平台草稿 Release。用户指定优先采用官方默认更新流程。

## 决定

- 延续固定版本 Wails v3.0.0-beta.24，保留 React/coss UI 和进程内代理 SDK。
- 使用官方 `app.Updater`、GitHub provider、默认窗口及 helper 替换/重启机制，不自行实现下载器或二进制替换。
- GitHub Release 是更新来源；客户端不携带 GitHub 凭据。版本在构建时由 tag 注入。
- 更新资产按平台/架构精确匹配。要求 SHA256SUMS 中有匹配项，不接受缺失校验元数据的资产。SHA-256 证明下载完整性，信任边界仍是 HTTPS 和仓库发布权限；它不等同于独立发布签名。
- macOS 更新 ZIP 包含 arm64/amd64 通用的完整签名、公证并 stapled 的 `.app`；DMG 用于首次安装。Windows ZIP、Linux tar.gz 包含 amd64 可执行文件。
- akproxy 使用新建的专用 Developer ID Application 证书、私钥和导出密码，以及仓库独立的公证凭据和 Secrets。不同应用不复用这些材料；Developer ID 本身仍为 Apple 团队级身份，并非单一 App 的权限边界。
- 采用官方默认的自动下载、用户点击重启流程及窗口语言。后台定时检查与手动检查共用更新器，避免并发检查破坏已下载状态。
- 开发构建不自动更新自身。生产构建才启用启动及每日检查。
- 常规本地构建版本为 `dev`，只有注入正式版本号的包启用更新。测试可在构建时注入本地 GitHub API 模拟地址；发布流程固定使用 GitHub 默认地址，没有运行时切换源入口。

## 备选与后果

保留 v2 并另接更新库需要独立维护平台安装和窗口；自定义窗口需要更多状态同步。采用 v3 beta 增加框架迁移与回归验证范围，但复用官方三平台安装链路，符合简单优先的选择。固定版本避免 CLI、Go 和前端 runtime 不匹配。

## 边界与验证

只修改应用安装文件，不改配置和账号目录。用户决定何时重启；正常退出路径停止代理。macOS 必须在可写安装位置运行，不能直接从只读 DMG 更新。Windows/Linux 的原生运行验收不在这台 Mac 上进行。

beta.24 默认窗口的 `Try Again` 仅重新下载已发现的版本，检查阶段网络失败时需要关闭窗口，从设置重新检查。保留官方窗口，不为此维护自定义模板或框架分叉。

验证版本选择、资产匹配、缺失/错误校验和下载后等待重启；构建前端与桌面包，并在 macOS 验证真实窗口和安装重启。公证凭据未配置时发布任务应失败，不能静默生成未签名正式包。
