# 用 React 和 coss ui 做窗口界面

状态：已接受

## 背景

窗口里的界面是侧边栏、当前页和导航栏上的一个服务按钮。用户指定用 React，组件库用 coss ui。Wails 模板自带的页面只是一个问候示例，不能承载这套形态。

## 决定

渲染层用 React。视觉组件使用 coss ui，按它的接入方式安装：Tailwind CSS v4，以及 coss 的样式和组件。界面状态里，配置、服务状态和账号列表是来自 Go 进程的数据；还没写完的输入留在对应页面。

不把 CLIProxyAPI 的管理面板嵌进窗口，也不自建一套平行的组件库。

## 备选

- 继续用 Wails 模板的手写 CSS。侧边栏、表单、对话框和按钮状态都要重做，和已经指定的组件库重复。
- 在窗口里打开管理面板网页。那是另一套信息架构，覆盖不了这里的侧边栏和单一服务按钮，还会下载外部面板资源。

## 后果

- 前端依赖用 pnpm。Wails v3 迁移后，`Taskfile.yml` 与 `build/config.yml` 的安装、开发和构建命令指向 pnpm。
- coss 组件通过它的注册表进仓库，主题令牌放在前端的全局样式里。
- Go 进程拥有配置、登录和服务生命周期。渲染层不直接读写配置文件。
- 文案是中文。按钮文字只用「启动」「停止」「重启」。

## 验证

- 窗口呈现 PRD 里的导航栏、侧边栏和当前页。设置改完就写入。
- 服务控制只有导航栏右侧那一个按钮。
