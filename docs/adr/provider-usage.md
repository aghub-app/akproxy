# 账号额度的数据边界与后台读取

状态：已接受（2026-09-23）

## 背景

现有 `AccountUsage(page)` 按账号读取厂商额度，`UsageWindow` 表示已用百分比和重置时间。产品要在原有账号卡片中增加 Grok、Devin、套餐、附加额度和设置，并让切换页面时复用已读结果。

## 决定

- 沿用 `AccountUsage` 和 `UsageWindow`。每个账号返回自己的套餐、窗口、可选附加额度、可选重置次数和错误。金额与积分按厂商单位传递，不把缺失字段转成零。前端沿用账号卡片和 `UsageBars`；不建立通用指标模型或第二套卡片布局。
- Go 在现有额度读取路径中解析各厂商响应。Codex 按 `limit_window_seconds` 区分 5 小时、每周和约 30 天窗口，`credits.balance` 保持积分单位。Claude 的套餐来自 profile 接口，失败只省略套餐名。Grok 的周窗口和按量上限来自 billing，套餐来自 settings；旧扁平响应仍可读，但月付窗口不标成每周。Devin 使用登录 metadata 的 `session_token` 实时调用 GetUserStatus 的 Connect-RPC JSON 接口，读取日/周窗口和超额余额，不用登录时的一次性配额快照。
- Grok 和 Devin 的额度契约依赖厂商响应。未知附加字段不影响可解析的窗口；请求失败按账号返回错误。Grok 令牌失效时不在额度读取中另做 OAuth 刷新。
- 偏好保存在应用的 `app.json`。读取旧文件时先填默认值再解码，保留用户明确关闭的选择。设置页修改后立即保存，不写进代理配置文件。
- 应用外层使用 TanStack Query 的账号列表和额度查询键。偏好加载且额度总开关开启后，仅对有已保存账号的页面读取，按 60 秒间隔刷新。账号页使用同一缓存，不在切换时重复请求；关闭总开关停止请求，新增或删除账号时刷新受影响页面。首次尚未读到时显示读取状态。Gemini 的额度来源见 `gemini-quota.md`。Kimi 的 Coding Plan 额度见 `kimi-quota.md`。

## 备选与后果

- 从登录 metadata 读取 Devin 配额能少一次请求，但数值停在登录时刻，因此使用实时接口。
- 另建持久化额度快照会引入过期状态；进程内缓存已满足页面切换复用，应用重启后重新读取。
- 重新设计通用指标类型会扩大 Wails 和前端接口变动；现有账号卡片只需要可选的附加字段。
- Grok、Devin 的非公开响应格式可能变化；解析或请求失败会显示在对应账号，不推算未经厂商确认的数值。

## 验证

用解析测试覆盖缺失字段、协议省略的零值、窗口周期和错误响应；用偏好测试覆盖旧文件默认值与明确关闭。前端构建及真实窗口检查卡片、设置和后台读取状态。
